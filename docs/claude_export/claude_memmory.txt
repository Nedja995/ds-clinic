Purpose & context

Ned is building DSKlinika (ds-clinic), a Windows-first Python desktop application for holistic medical clinics. The app uses AI to analyze patient documents and generate structured PDF reports. It is a solo development project, actively evolving across versioned directories under D:\__STORAGE\__DEV\__PROJECTS\DSKlinika\, with the active version at ds-clinic_03_04_2026.

Architecture & stack: Python, tkinter/ttk (GUI), FPDF2 (PDF generation), Pydantic v2 (data models), MVVM pattern, PyInstaller (distribution). AI integrations include both Google Gemini (api_gemini) and Anthropic Claude (api_claude) via their respective native SDKs. Configuration uses a three-tier system (JSON + INI + TOML).

Core modules: report_view.py, report_view_models.py, models.py, pdf_maker.py, styles.py, main_container.py, config.py, npy/core/utils.py.

Key learnings & principles

Minimal, pattern-matched changes are preferred: Ned explicitly favors targeted edits modeled on existing code patterns over refactored abstractions, even if it means some duplication.
Drop-in compatibility matters: Refactors should not require changes to other layers (e.g., controller/ViewModel changes when the View is refactored).
ttk throughout, with documented exceptions: tk.Canvas, scrolledtext.ScrolledText, and tk.StringVar are the three intentional tk.* carve-outs; all other widgets use ttk.* with named styles via ttk.Style.
Threading discipline: Worker threads only write to queue.Queue; all UI updates happen exclusively on the main thread via root.after() polling. event_generate must never be called from worker threads.
Native SDKs over abstraction layers: The project uses google-genai and anthropic SDKs directly rather than proxies like liteLLM, for lower overhead and direct access to model-specific parameters.
Claude API cost note: Embedding JSON schema in the system prompt (required for structured output without response_schema) adds tokens per request — acceptable but worth tracking.
A known bug was identified: a "processing" status branch incorrectly sets the status title to "Failed" in the queue loop.

Approach & patterns

Code exploration before writing: Claude reads existing files (styles, views, models) before implementing anything, to match visual and structural conventions precisely.
Incremental file writing: Long files are built in logical chunks using append mode rather than single large writes — reliable for files exceeding ~30 lines.
File navigation discipline: Always use list_directory to confirm exact filenames before reading (filenames have tripped up search-based lookups, e.g., singular vs. plural report_view_model(s).py).
Specification-driven development: Ned has produced both a technical spec (DSClinic_SPEC.md) and a client-facing product spec (DSClinic_Product_SPEC.md) to guide development.
